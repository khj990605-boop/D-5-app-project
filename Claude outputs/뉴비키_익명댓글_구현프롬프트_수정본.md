# 뉴비키 용어 상세페이지 익명 댓글 기능 — 구현 프롬프트 (수정본)

## 0. 가장 중요한 원칙 (모든 요구사항보다 우선)

1. **기존 기능에 영향을 주지 않는다.** 이번 작업은 "추가"만 한다. 기존 코드는 댓글을 붙이는 데 꼭 필요한 최소한만 건드린다.
2. **디자인을 바꾸지 않는다.** 새 색·폰트·그림자를 만들지 말고, `index.html` 맨 위 `:root`에 이미 있는 CSS 변수(`--color-primary`, `--color-border`, `--radius-lg` 등)와 기존 클래스(`.btn-primary`, `.textarea`, `.field-msg`, `.d-empty`, `.toast` 등)를 그대로 재사용한다.
3. 시안 이미지와 이 문서가 다르면 **이 문서를 따른다.** (예: 시안의 `...` 메뉴, 모바일 상단의 북마크·공유 버튼은 만들지 않는다)

작업 후 아래가 이전과 똑같이 동작해야 한다: 홈, 검색(초성 포함), Ctrl K 검색창, 카테고리, 용어 상세의 기존 섹션과 목차, 검색 결과 없음, 등록 요청, 나도 궁금해요, 구글 시트 → 저장본 → data.js 순서의 용어 불러오기.

## 1. 현재 구조 (새로 파악할 필요 없음)

- **프론트엔드:** 저장소 루트의 `index.html` 한 파일 (빌드 없음, 프레임워크 없음, Vercel 정적 배포). `data.js`는 비상용 데이터.
- **백엔드:** 구글 Apps Script 웹 앱 1개. 주소는 `index.html`의 `NEWBIKEY_API` 상수.
  - `GET NEWBIKEY_API` → 용어집 시트 내용 + 요청 수
  - `GET NEWBIKEY_API?only=requests` → 요청 수만
  - `POST NEWBIKEY_API` (본문 JSON, `Content-Type: text/plain;charset=utf-8`로 보내서 CORS preflight 회피) → `type: "request"` / `"metoo"`를 「뉴비키 등록 요청」 시트 「요청」 탭에 저장
- **Apps Script 소스는 저장소에 없다.** 구글 Apps Script 편집기에 있다.

**새 DB·새 서비스(Supabase, Firebase 등)를 추가하지 않는다.** 댓글도 같은 Apps Script와 「뉴비키 등록 요청」 스프레드시트에 붙인다.

## 2. 만들어야 할 결과물

### A. Apps Script에 붙여 넣을 코드 (`apps-script/comments.gs`로 저장소에도 보관)
- 기존 `doGet` / `doPost`를 덮어쓰지 않는다. 기존 함수 맨 앞에 아래처럼 **분기 한 줄씩만** 추가하고, 나머지 로직은 새 함수로 분리한다.
  - `doGet`: `if (e.parameter.only === "comments") return handleCommentsGet_(e);`
  - `doPost`: 본문의 `type`이 `"comment"` 또는 `"like"`이면 `handleCommentPost_(body)`로 보내고 return. 그 외(`request`, `metoo`)는 기존 그대로.
- 어디에 몇 줄을 넣는지 **사람이 따라 할 수 있게 단계별 안내**도 같이 써 준다 (기존 코드를 모르는 상태에서도 붙일 수 있게).
- 수정 후에는 **「배포 관리 → 기존 배포 수정 → 새 버전」**으로 배포해야 주소(`NEWBIKEY_API`)가 바뀌지 않는다는 안내를 꼭 포함한다. "새 배포"를 만들면 주소가 바뀌어 앱 전체가 깨진다.

### B. `index.html` 수정
- 상세 화면(`renderDetail`)의 `<footer class="trust">` **바로 아래**(article 안, 마지막)에 댓글 영역 컨테이너 하나만 추가한다.
- 댓글 관련 JS는 기존 코드 사이에 섞지 말고 `/* ───── 익명 댓글 ───── */` 블록 하나로 모은다.
- CSS도 `/* ── 익명 댓글 ── */` 블록 하나로 `<style>` 끝에 추가한다. 기존 규칙은 수정하지 않는다.
- 우측 목차(`.toc`)에는 항목을 추가하지 않는다.

## 3. 시트 구조 (「뉴비키 등록 요청」 스프레드시트에 탭 2개 추가)

**「댓글」 탭** — 1행 머리글
| 댓글ID | 용어ID | 익명번호 | 내용 | 작성시각 | 숨김 |
|---|---|---|---|---|---|
- 댓글ID: `Utilities.getUuid()`
- 작성시각: 실제 시각 (ISO 문자열)
- **숨김:** 관리자가 체크박스(TRUE)로 바꾸면 앱에 보이지 않는다. 사용자용 삭제는 없지만 관리자는 이걸로 내린다.

**「좋아요」 탭** — 1행 머리글
| 댓글ID | 브라우저ID | 시각 |
|---|---|---|

탭이 없으면 코드가 처음 실행될 때 머리글과 함께 자동으로 만든다.

## 4. 동시성 처리 (필수)

Apps Script에는 DB 트랜잭션이 없으므로 **`LockService.getScriptLock()`**으로 처리한다.

**댓글 작성**
```
lock.waitLock(10000)
→ 「댓글」 탭에서 해당 용어ID의 최대 익명번호 조회
→ +1 해서 행 추가 (appendRow)
→ SpreadsheetApp.flush()
→ lock.releaseLock()   (finally에서)
```
- 익명번호는 **서버(Apps Script)에서만** 계산한다. 클라이언트에서 계산하지 않는다.
- 용어별로 1부터 시작한다. (PBC: 익명 1, 2, 3 / 금조: 익명 1, 2)
- 잠금을 못 얻으면 `{ ok: false, error: "busy" }`를 돌려준다.

**좋아요**
```
lock.waitLock(10000)
→ 「좋아요」 탭에 (댓글ID, 브라우저ID) 행이 이미 있으면 → 변화 없이 현재 수 반환
→ 없으면 행 추가 → flush
→ 해당 댓글의 좋아요 수(「좋아요」 탭에서 센 값) 반환
```
- 좋아요 수는 「좋아요」 탭을 세어서 만든다 (별도 카운트 칸을 두지 않는다).
- 좋아요 취소는 없다.

## 5. API 형태

**조회:** `GET NEWBIKEY_API?only=comments&term=<용어ID>&browser=<브라우저ID>`
```json
{ "ok": true, "comments": [
  { "id": "...", "number": 3, "content": "...", "createdAt": "2026-10-06T09:12:00Z", "likes": 2, "liked": true }
] }
```
- 숨김 처리된 댓글은 빼고, **작성시각 내림차순**(최신이 위)으로 보낸다.
- `liked`는 요청한 브라우저ID가 좋아요를 눌렀는지 여부.

**작성:** `POST` 본문 `{ "type": "comment", "term": "<용어ID>", "content": "..." }`
→ `{ "ok": true, "comment": { ...위와 같은 형태, "likes": 0, "liked": false } }`

**좋아요:** `POST` 본문 `{ "type": "like", "commentId": "...", "browser": "<브라우저ID>" }`
→ `{ "ok": true, "likes": 3, "liked": true }`

**서버 검증 (Apps Script에서도 반드시)**
- content는 trim 후 1~500자. 아니면 `{ ok:false, error:"length" }`
- 용어ID는 용어집 시트에 실제로 있는 id인지 확인
- 시트에는 받은 텍스트를 그대로 저장하고, 화면에 그릴 때 기존 `esc()` 함수로 escape한다 (innerHTML에 날것으로 넣지 않는다)
- 브라우저ID는 36자 이하 영문·숫자·하이픈만 허용

POST는 기존과 같이 `Content-Type: text/plain;charset=utf-8`로 보낸다.

## 6. 브라우저 ID

- 처음 필요할 때 `crypto.randomUUID()`로 만들고 localStorage `newbikey.browserId`에 저장 (기존 키 `newbikey.*` 규칙을 따름).
- localStorage 접근은 기존 코드처럼 try/catch로 감싼다. 저장이 막힌 환경에서도 앱이 멈추지 않아야 한다.
- 좋아요 중복 방지 외 용도로 쓰지 않는다.
- 댓글 자체는 localStorage에 저장하지 않는다 (시트가 원본).

## 7. 화면

댓글 영역은 **제목·아이콘·설명 헤더 없이 입력창부터 시작**한다.

```
[ 댓글 textarea                                   ]
[ 고객사명 등 업무상 기밀은 적지 말아 주세요   0/500 ]
                                  [ 댓글 작성하기 ]
──────────────────────────────────────────────────
댓글 12개                                    최신순
┌ 익명 3  방금 전                          ♥ 2 ┐
│ 이번에 처음 알았는데 설명이 이해하기 쉬워요.   │
└──────────────────────────────────────────────┘
```

- **입력창:** 기존 `.textarea` 클래스. placeholder `댓글을 입력해주세요. (이름 입력 없이 익명으로 작성됩니다.)`
- **입력창 아래 한 줄:** 기존 `.field-msg` 형태로 왼쪽에 `고객사명 등 업무상 기밀은 적지 말아 주세요`, 오른쪽에 글자 수 `0/500`. 500자 넘으면 숫자를 `--color-danger`로.
- **버튼:** 기존 `.btn-primary`. PC는 오른쪽 정렬·자동 너비, 모바일(767px 이하)은 전체 너비. 내용이 없거나 500자 초과면 disabled. 보내는 중엔 disabled + "작성 중…".
- **구분선:** `1px solid var(--color-border)`
- **목록 머리:** 왼쪽 `댓글 N개`(N은 숫자), 오른쪽 `최신순` 텍스트만 (정렬 메뉴 없음)
- **댓글 카드 (PC):** `background: var(--color-bg)`, `border: 1px solid var(--color-border)`, `border-radius: var(--radius-lg)`, `padding: 20px 24px`, 그림자 없음
  - 첫 줄 왼쪽: `익명 N`(600, `--color-text`) + 시간(13px, `--color-text-tertiary`)
  - 첫 줄 오른쪽: 하트 + 숫자. 안 누름 = 빈 하트, `--color-text-tertiary` / 누름 = 채운 하트, `--color-primary` / hover = 색만 `--color-primary`, 배경 없음
  - 본문: 15px, line-height 24px, `--color-text-body`, 줄바꿈 유지(`white-space: pre-wrap`), 긴 단어 줄바꿈(`overflow-wrap: anywhere`)
- **댓글 카드 (모바일):** 카드 테두리 대신 위아래 구분선만, 좌우 padding 0, 위아래 18px
- **넣지 않을 것:** `...` 메뉴, 주황 배지·원형 도형, 제목, 아이콘 헤더, 답글, 수정, 삭제, 신고, 이름 입력, 좋아요 취소
- **하트 아이콘:** 기존 아이콘처럼 인라인 SVG (`svg.i` 스타일)

**시간 표시:** 1분 미만 `방금 전` / `N분 전` / `N시간 전` / `N일 전` / 7일 이상은 기존 `fmt()`처럼 `2026.10.06`

**빈 상태:** 기존 `.d-empty` 스타일로
`아직 댓글이 없어요. 이 용어에 대한 경험이나 팁을 가장 먼저 남겨보세요.`

## 8. 동작

- **불러오기:** 상세 화면을 그린 **뒤에** 댓글을 따로 불러온다. 댓글 요청이 느리거나 실패해도 상세 화면의 나머지는 이미 다 보여야 한다.
  - 불러오는 동안: 목록 자리에 기존 `.skel` 회색 블록 2개
  - 실패: `댓글을 불러오지 못했어요. 잠시 후 다시 시도해주세요.` (작은 `.d-empty` 문구, 입력창은 그대로 보임)
  - 타임아웃 8초 (용어 불러오기 `boot()`의 8초와 동일하게, AbortController 사용)
- **다른 용어로 이동하면** 이전 용어의 늦게 도착한 응답이 새 화면에 그려지지 않게 막는다 (응답의 용어ID와 현재 화면 용어ID 비교).
- **작성 성공:** 입력창 비우기 → 서버가 돌려준 댓글을 목록 맨 위에 추가 → `댓글 N개` +1
- **작성 실패:** 입력 내용은 그대로 두고 기존 `toast()`로 `댓글 등록에 실패했어요. 잠시 후 다시 시도해주세요.` (댓글은 기존 요청처럼 outbox에 모아 재전송하지 않는다 — 번호가 꼬일 수 있음)
- **좋아요:** 요청 중엔 버튼 disabled. 화면은 **성공 응답을 받은 뒤** 서버가 준 숫자로 바꾼다. 이미 누른 하트는 다시 눌러도 요청을 보내지 않는다.
- 한글 입력 중(`isComposing`) Enter로 제출되지 않게 한다. 제출은 버튼으로만.

## 9. 테스트 (완료 전에 직접 확인)

**기존 기능 회귀 (가장 먼저)**
- [ ] 홈·검색·초성 검색·Ctrl K·카테고리·검색 결과 없음·등록 요청·나도 궁금해요가 이전과 같게 동작
- [ ] Apps Script 주소에 접속이 안 될 때도 용어 화면은 저장본/data.js로 뜨고, 댓글 영역만 실패 문구
- [ ] PC 1280px / 태블릿 768px / 모바일 390px에서 상세 화면 레이아웃과 목차가 그대로이고 가로 스크롤 없음

**댓글**
- [ ] PBC 첫 댓글 → 익명 1, 두 번째 → 익명 2, 금조 첫 댓글 → 익명 1
- [ ] 새로고침 후 유지, 최신 댓글이 맨 위
- [ ] 빈 댓글·공백만·501자 등록 불가 (화면과 서버 둘 다)
- [ ] `<script>alert(1)</script>`를 댓글로 쓰면 글자 그대로 보임
- [ ] 두 브라우저에서 거의 동시에 작성 → 익명번호 중복 없음
- [ ] 시트에서 「숨김」 체크 → 새로고침 시 사라짐

**좋아요**
- [ ] 첫 클릭 +1, 새로고침 후 채운 하트 유지
- [ ] 같은 브라우저에서 다시 눌러도 그대로
- [ ] 다른 브라우저(시크릿 창)에서는 추가로 누를 수 있음
